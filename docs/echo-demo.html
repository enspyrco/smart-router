The problem

Most AI apps overpay.

A trivial "reverse this word" and a hard multi-step problem both get sent to the same expensive model.

You're paying premium prices for easy questions, because nothing sorts the easy ones from the hard ones.

The usual fix needs training data. What if we needed none?

Why this is worth doing — per million tokens

The expensive model
costs 3× the cheap one.

Route an easy question to the cheap model and you pay a third. Route it to a specialist on your own laptop and you pay nothing per call - just electricity. That's the prize.

The idea

Let the cheap model
check itself.

  • Ask the cheap model the same question twice, worded two different ways.
  • Same answer both times → it was easy. Keep it.
  • Two different answers → it's shaky here. Escalate to the big model.

If a student gives the same answer no matter how you ask, they know it. If the answer flips, they're guessing — get a second opinion.

Plot twist #1

Our first results
were a lie.

On a reasoning test, the cheap and expensive models scored identically low (≈0.14). Suspicious — the big one should win.

Our test rig was accidentally feeding the model our whole project setup, so it answered as our assistant, not as a clean model. We were measuring the wrong thing.

The thermometer was broken. The numbers weren't low because the idea failed — they were low because we were measuring wrong. A 30-second check caught it.

The clean result

The cheap model is
now as good as the big one.

reasoning testscore
Haiku (cheap)0.848

hardest questionsboth perfect

On these tests, the cheap model ties the expensive one. The test is "saturated."

Saturated = the test got so easy that even the cheap model aces it. So "escalate to the smarter model" has nothing left to escalate to. Our original idea just hit a wall.

Plot twist #2

But routing
still won.

The two models tie on average — yet picking the right one per question beat both.

They score the same overall, but they get different questions wrong. So if you always ask the one that happens to be right, you win — even though neither is "better."

The value isn't a smarter model. It's two models that fail in different places.

The pivot · idea by Connor Hood

Route by the subject,
not the difficulty.

  • Difficulty is a dead end now (cheap ties expensive).
  • Instead, send each question to a specialist — a small model that owns that one subject.
  • It only needs to beat the generalist on its home turf, not everywhere.

Don't ask "is this hard?" Ask "is this a maths question?" and send it to the maths model.

We checked the literature · 27 papers, fact-checked

Real — but only
in some subjects.

  • Maths: a tiny 7-billion model beats GPT-4-class models specialist wins
  • Code: the tiny model loses badly to the big ones big model wins
  • The dispatcher can be tiny and cheap — a 0.5B model picks the subject in a blink.

"7B" = 7 billion parameters, a small model you can run on a laptop. Specialists win at maths, lose at code. So we test on maths first.

The experiment · run overnight · on this laptop · $0

Three small models,
100 maths questions.

A general small model, a maths specialist, a code specialist. Each answers all 100. No big model, no cloud, no cost.

The one question that could kill the idea: do they get the same questions wrong, or different ones?

If they all fail on the same questions, routing is pointless. If they fail on different ones, routing is gold.

Even on maths, the maths specialist isn't always the best one. Sometimes the generalist saves the day. That two-way rescue is exactly the free score we're harvesting.

The honest question: is free also slow?

Free — and about as fast
as a cloud call.

on this laptopper answer
the router (tiny)~1–2 s
general / code model~10 s
maths specialist~15 s

Roughly the same as a cloud model call. You trade the network trip and the fee for local compute.

Speed rides on the hardware. On this Apple-silicon laptop a specialist answers in about the time a cloud call would; on a weak or CPU-only machine it would drag. So this is a "good laptop or a GPU" story, not a "runs anywhere" one. The maths specialist is slowest because it thinks step by step before answering - which you're about to watch, live.

The honest catch

"Pick the right one"
is a cheat.

That 0.90 peeks at the answer key. The real challenge: can a cheap dispatcher pick the right model without already knowing the answer?

The ceiling is real and big. The open research question is how much of it a practical, no-peeking router can actually reach.

Our clue: asking a model if it agrees with itself isn't enough — models confidently agree on wrong answers too. The next step is measuring genuine disagreement.
