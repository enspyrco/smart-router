Hyperspecialist Routing

Echo research brief · route by task TYPE, not difficulty · 4 July 2026 · idea by Connor Hood, verified via deep-research harness (23/25 claims survived 3-vote adversarial review)

TL;DR. Connor's pivot is structurally correct: difficulty-based routing's payoff shrinks as the model gap shrinks, and saturation (Haiku ties Sonnet) is precisely the zero-gap regime where a difficulty signal has nothing to route on. Type-based routing to small domain specialists sidesteps that axis entirely. The evidence is real but conditional: a 7B math specialist genuinely beats GPT-4o on MATH, but a 7B code specialist loses hard to frontier models on code. The specialist win is domain-specific, not categorical.

The biggest finding is not about routing at all. It is a direct threat to Echo's own mechanism: self-consistency fails to capture the decorrelated-error ceiling (the "popularity trap" - models agree on identical wrong answers). And we have already measured this tax in our own BBH data. See section 5.

1. Why now: saturation killed the difficulty thesis

Echo's original bet was a difficulty ladder: two cheap attempts, and if they disagree the task is hard, so escalate to the expensive model. Our clean BBH re-run (n=99) showed that ladder has collapsed for 2026 Claude - Haiku and Sonnet both score 0.848, identical subtask-for-subtask, and on the hardest BBH subtasks both hit a perfect 33/33. There is no difficulty gap left to route on.

The literature predicts exactly this failure. Hybrid-LLM (ICLR 2024) shows difficulty routing's payoff is a function of the model gap: with a close pair you route 20-40% of queries to the cheap model at roughly 0% quality loss, but the whole mechanism only pays when the two models actually differ. Saturation is the small-gap regime. This is the strongest structural argument for Connor's pivot: stop routing on a difficulty axis that no longer exists, and route on task type instead, where the question is not "is this hard?" but "which specialist owns this?"

2. Does a 7B specialist beat the frontier?

This is the load-bearing claim, and the honest answer is: it depends on the domain. The adversarial verification split cleanly.

DomainSpecialist vs frontierVerdict
MathQwen2.5-Math-7B-Instruct scores 83.6 on MATH (chain-of-thought) vs GPT-4o's 81.1. A ~10x smaller model wins outright, and also beats the 72B general Qwen2 model.specialist wins
CodeQwen2.5-Coder-7B scores 61.6% on HumanEval - beats older big code models (DeepSeek-Coder-33B at 54.9%) but loses badly to frontier generalists (Claude-3.5-Sonnet / GPT-4o at ~92%).frontier wins

So "hyperspecialist beats frontier on its own turf" is true for math, false for code. The implication for the experiment: aim first at math-like domains, where the effect is real and large. Chasing code is aiming at the one domain where the evidence says the 7B loses.

Caveat: these are first-party vendor benchmarks

The Qwen2.5-Math and Qwen2.5-Coder numbers come from Alibaba's own technical reports (arXiv 2409.12122, 2409.12186). Standard cherry-pick risk applies. The direction survives across metric variants and independent adversarial review, but the exact headline numbers should be read as vendor-favorable. The one clean specialist-beats-frontier result (math, CoT) clears GPT-4o even without the tool-integrated-reasoning boost the report also reports.

3. Two kinds of routing, and the cost of the classifier

The field has two canonical pre-generation strategies, and they are genuinely distinct:

  • Type routing (MoDEM, Arch-Router): infer the query's domain, send it to a domain-expert model. Explicitly decoupled from predicting which model is "best" or how hard the query is.
  • Difficulty routing (RouteLLM, Hybrid-LLM, FrugalGPT): pick stronger-vs-weaker purely on predicted per-query quality gap. This is Echo's current axis.

Type routing is viable because the classifier is cheap. A 1.5B router (Arch-Router) classifies task type at 93% accuracy in ~51ms - beating GPT-4o and Claude-3.7-Sonnet as routers. A 304M DeBERTa domain classifier (MoDEM) hits ~97%. The classifier cost is a small fraction of one inference call.

But type routing has an Achilles heel: the "other" / out-of-category query. MoDEM's router classifies specialized domains at 77-97% accuracy but collapses to ~53% on general/ambiguous queries. A production stream with no ground-truth category label could pay a far larger misroute tax than any benchmark suggests. Any real Echo router needs a confident fallback to the generalist when type is unclear.

4. Decorrelated errors: the real oracle ceiling

The mechanism that makes routing worth anything is that different models fail on different items. The strongest evidence: an ensemble oracle ceiling up to 83% above the best single model (Wisdom/Delusion of LLM Ensembles, Oct 2025), driven by complementarity - even a CodeLlama-7B solves problems the top models miss. This ceiling can be wider headroom than a difficulty signal ever captures, and it is exactly what a type-router tries to harvest: a specialist that fails on different items than the generalist lifts the oracle.

This is the same shape as our own BBH oracle result: echo-oracle beat both baselines (0.899 vs 0.848) entirely because Haiku and Sonnet failed on different causal-judgement items. The decorrelation is real. The question the experiment must answer is whether it persists between a 7B specialist and a generalist within a single MMLU-Pro category.

5. The threat to Echo, measured in our own data

The finding that matters most. Self-consistency / consensus selection fails to capture the decorrelated-error oracle gain. The Oct 2025 ensemble paper calls it the "popularity trap": models agree on identical wrong answers, so a consensus signal performs worse than a naive baseline. Only a diversity-based aggregator recovers the ceiling.

Echo's cost signal is self-consistency: do two cheap attempts agree? This paper says that signal is structurally leaky, because agreement and correctness decouple exactly where the errors are decorrelated - which is the very place the oracle gain lives.

And we have already measured the tax. Our clean BBH n=99 numbers:

ArmAccuracyWhat it is
echo-judge (deployable)0.869the agreement signal we can ship
echo-oracle (ceiling)0.899route perfectly on ground truth
gap = 0.030the popularity-trap tax, in our own harness

That ~3-point gap between our agreement signal and the oracle is not noise and not a judge-quality problem to be fixed with a smarter judge. The literature reframes it precisely: the lever is a diversity aggregator, not a better one. This recasts open issue #619 (filed as "cross-family judges") - the deeper fix is to measure disagreement diversity, not to make the agreement detector sharper.

6. The experiment: a confusion table that kills or keeps the thesis

The cheapest falsifier is not a full routed system. It is a single per-category confusion table. Running now on the M1 Max (local Ollama, zero Claude quota):

  • Models: a general 7B (Qwen2.5-7B-Instruct) plus domain specialists (Qwen2.5-Math-7B, Qwen2.5-Coder-7B), all local GGUF.
  • Data: MMLU-Pro, categories math and computer science, N=100 items each.
  • Measure: per-category accuracy per model, and item-level decorrelation - the count of items where the specialist is right and the generalist wrong (and vice versa), plus the oracle best-of ceiling.

Kill-conditions. The thesis dies cheap if, in-domain, either (a) the specialist does not beat the general 7B, or (b) errors are correlated - the specialist rescues nothing the generalist already gets, so the oracle sits on top of the best single model with no lift.

Instrument note: the parser fix that had to come first

The math specialist emits \boxed{A} (LaTeX), not "Answer: A". On the first smoke test every math-model answer scored "unparseable" - a pure format failure that, run at scale, would have produced math_specialist ≈ 0% and a false "7B math models can't do MMLU-Pro" conclusion. A 30-second raw-output dump caught it. The parser now recognizes boxed answers (committed with regression tests, suite green at 33 passing). This is the same class of bug as the BBH contamination: an instrument silently measuring the wrong thing. Fire the cheap falsifier before the hypothesis cements.

7. Open questions

  1. Within-category vs across-category decorrelation. All the cited oracle-gap evidence is code-gen/repair. Does per-item decorrelation between a 7B specialist and a generalist actually exist inside a single MMLU-Pro category? If within-category errors are correlated, the oracle ceiling collapses and the thesis dies.
  2. Does a local 7B beat saturated frontier Claude, or only a cheaper generalist? If the specialist only wins against other cheap models, type routing optimizes cost among cheap models but never displaces the frontier - a much weaker thesis. Math is the one domain where it might genuinely beat frontier. This is the second experiment: add a Claude arm per category.
  3. The real "other"-query tax. MoDEM's 53% is classification accuracy on clean labels. A production stream has no ground-truth category, so the misroute tax could swamp the specialist gains.
  4. Can a diversity aggregator run cheaply on CPU? The ensemble paper shows self-consistency fails and diversity needs multiple model calls - which may erase the very cost advantage that motivated routing.
